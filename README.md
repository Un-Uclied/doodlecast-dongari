# DOODLECAST

**마우스로 그린 낙서가 마법이 되는 2D 액션 게임**

파이게임부 동아리 발표회를 위해 만든 1인 개발 게임입니다. 최종 버전은 **1.1.1**입니다.

- [Windows 게임 다운로드](https://github.com/Un-Uclied/doodlecast-dongari/releases/latest)
- [동아리 실시간 순위 사이트](https://un-uclied.github.io/doodlecast-dongari/)

## 게임 소개

플레이어는 마법사가 되어 마왕성 던전의 여섯 레벨에 도전합니다. 적 머리 위에 표시된 기호를 마우스로 그리면 마법이 발동합니다. 같은 기호를 가진 여러 적을 한 번에 공격할 수 있어서, 적의 패턴을 읽고 어느 주문을 먼저 그릴지 판단하는 것이 중요합니다.

가로선·세로선·체크 모양부터 별과 회오리까지 여러 기호를 사용합니다. 적중과 처치를 이어가면 콤보가 D에서 S까지 올라가고 점수 배율도 높아집니다. 이동하고 대시하며 적의 공격을 피하는 동시에, 당황하지 않고 기호를 그려야 합니다.

기본 보병과 오크 외에도 빠르게 달려오는 적, 플레이어 주위를 도는 박쥐, 탄막을 발사하는 눈, 가로 또는 세로로 긴 불 레이저를 쏘는 불꽃 정령이 등장합니다. 레이저가 발사되기 전에는 붉은 경고 영역이 차오르므로 공격 방향을 보고 피할 수 있습니다.

EASY·NORMAL·HARD는 각각 수정할 수 있는 맵을 사용합니다. 전투 중 등장하는 회복 하트는 몸으로 닿아서 얻는 대신 하트 기호를 그려 획득합니다. 여섯 레벨을 모두 완료하면 승리 캐릭터와 축하 문구, 콘페티, 환호음으로 클리어를 축하합니다.

## 실행 방법과 조작

Windows ZIP을 다운로드해 압축을 풀고 `DOODLECAST.exe`를 실행합니다. 게임 데이터가 실행 파일에 포함되어 있어 Godot 설치나 별도의 Firebase 환경 설정은 필요 없습니다. 시작할 때 숫자 다섯 자리의 학번을 입력하며 이름은 선택입니다.

처음이라면 학번 입력칸 오른쪽 **튜토리얼**에서 먼저 연습할 수 있습니다. 1.1.1에 추가된 연습장으로, 학번 없이 시작합니다. 「지팡이 선배」의 짧은 안내에 따라 이동·대시 → 여섯 공격 기호 → 하트 회복을 직접 배웁니다. 기호를 그리는 순서도 예시로 보여줍니다. 연습용 적은 공격하지 않으며 튜토리얼 기록은 순위에 올라가지 않습니다.

| 입력 | 동작 |
| --- | --- |
| WASD | 이동 |
| Shift | 대시 |
| 마우스 왼쪽 버튼 드래그 | 기호를 그려 마법 시전 |
| 마우스 오른쪽 버튼 | 그리던 기호 취소 |
| Esc | 그리기 취소 / 일시정지 |

게임 오버 또는 전체 클리어 시 최종 기록을 저장합니다. 인터넷이 끊겨 있으면 기록을 PC에 보관하고 연결이 가능해졌을 때 다시 전송합니다. 메인 메뉴로 중도 종료한 판은 순위에 올리지 않습니다.

## 사용한 기술과 선택 이유

| 기술·도구 | 사용한 부분 |
| --- | --- |
| **Godot 4.7.1 / GDScript** | 2D 전투, 기호 인식, 적 행동, 맵, 메뉴와 게임 진행 |
| **Godot Shader / 파티클 / Tween** | 공격 범위 경고, 마법·피격·회복 효과, 조명, 화면 전환과 UI 애니메이션 |
| **OpenAI Codex** | 구현 보조, 오류 분석, 코드 수정, 기능을 연결하고 정리하는 작업 |
| **ChatGPT / GPT 이미지 생성** | 캐릭터·장식 이미지 등 일부 시각 자료 제작 |
| **Firebase Authentication / Cloud Firestore** | 익명 로그인, 게임 기록 저장, 실시간 순위 데이터 제공 |
| **HTML / CSS / JavaScript** | 동아리 발표회 순위 사이트 |
| **Git / GitHub / GitHub Pages** | 버전 관리, 소스 공개, 게임 배포와 사이트 호스팅 |

이 프로젝트에서는 상대적으로 무거운 Unity 환경 대신, 작은 2D 게임을 가볍게 만들고 수정하기 좋은 Godot를 선택했습니다. GDScript와 텍스트로 저장되는 씬 파일을 사용하기 때문에 AI가 코드를 읽고 수정하기에도 편했습니다. 메뉴와 결과 화면도 `.tscn` 씬의 노드로 구성해 Godot 에디터에서 직접 배치와 디자인을 수정할 수 있게 했습니다.

이미지는 GPT로 제작한 자료와 기존 픽셀 애셋을 함께 사용했습니다. 생성한 그림을 넣는 데서 끝내지 않고 게임의 보라색·금빛 분위기에 맞춰 조명, 효과, 화면 구성을 조정했습니다. 순위 사이트는 게임의 색상으로 바꾸지 않고 동아리의 파랑·흰색 디자인을 유지했습니다.

## 내가 맡은 역할과 개발 기록

1인 개발로 게임의 기획, 디자인 방향, 난이도와 점수 규칙, 플레이 피드백, 최종 기능 선택을 맡았습니다. Codex에는 필요한 동작을 구체적으로 설명해 구현을 보조하게 하고, 직접 게임을 플레이하면서 어색하거나 불편한 부분을 찾아 수정 방향을 정했습니다.

처음에는 적 머리 위의 기호를 그려 공격하는 기본 전투에서 시작했습니다. 이후 무적 시간과 대시, 적 사이의 간격 유지, 구덩이를 피하는 이동을 추가했습니다. 단순히 적의 수만 늘리기보다 움직임과 공격 방식이 다른 적을 만들고, 불 레이저처럼 미리 보고 피할 수 있는 공격을 넣어 전투에 변화를 주었습니다.

기호 인식도 플레이하면서 계속 조정했습니다. 별과 회오리가 잘 인식되지 않는 문제, 멀리 있는 적에게 공격이 들어가지 않는 문제, 넓고 둥근 하트가 실패하는 문제 등을 피드백해 개선했습니다. 콤보 게이지와 스폰 속도, 난이도별 점수 배율도 실제 플레이 느낌을 기준으로 여러 차례 조정했습니다.

화면 연출에서는 처음의 차갑고 기계적인 느낌을 줄이고 신비로운 마법 분위기를 만드는 데 신경 썼습니다. 보라색과 노란색을 중심으로 환경을 어둡게 하고, 횃불 조명과 마법 파티클, 카메라 흔들림, 시전 성공·실패·피격 효과를 더했습니다. 게임 오버 화면의 가독성과 메뉴 이동 확인창도 다듬고, 마지막 승리 화면에는 캐릭터 이미지와 축하 연출을 넣었습니다.

마지막으로 게임을 다른 컴퓨터에서도 별도 설정 없이 실행할 수 있게 정리하고, 동아리 사이트에 실제 기록이 반영되도록 연결했습니다. AI를 구현 도구로 활용하면서도 어떤 게임을 만들지, 무엇을 바꾸고 어디까지 완성할지는 직접 결정하며 프로젝트를 마무리했습니다.

처음 플레이하는 사람도 바로 적응할 수 있도록 마지막에 짧은 튜토리얼을 더했습니다. 긴 설명을 읽는 대신 직접 움직이고 주문을 그려 보면서, 공격과 회복에 필요한 기본 조작을 익히도록 구성했습니다.

## 실시간 순위와 개인정보 표시

게임 기록은 Firestore의 `doodlecast_runs`에 저장하고, 사이트에는 학번별 최고 기록을 표시합니다. 순위는 점수, 피격 횟수, 서버 저장 시각 순으로 정합니다. 난이도·도달 레벨·전체 클리어 여부·처치 수·피격 수·플레이 시간도 함께 표시합니다.

학번 다섯 자리는 앞의 0을 포함해 전부 표시합니다. 이름은 `홍*동`처럼 가운데를 가려 전송하며, 입력한 이름 원문은 서버에 보내지 않습니다. 익명 로그인 정보와 미전송 기록은 Windows의 `%APPDATA%/Godot/app_userdata/DOODLECAST/leaderboard/`에 저장합니다.

Firebase 클라이언트 API 키는 공개 앱 설정값이며, 관리자 키는 게임이나 저장소에 포함하지 않습니다. 인증과 Firestore 보안 규칙으로 기록의 필드와 값의 범위를 검사합니다. 클라이언트에서 계산한 점수의 실제 플레이 여부를 검증하는 서버는 구현하지 않았습니다. 자세한 내용은 [보안 안내](docs/security.md)를 참고하세요.

Godot 4.7.1에서 `project.godot`를 열어 편집할 수 있습니다. 게임 구조와 조정 항목은 [전투·레벨 문서](docs/combat.md)에 정리했습니다.

사이트는 [기존 동아리 사이트](https://github.com/Un-Uclied/pygamebu-dongari/tree/main/docs)의 디자인을 이어 사용합니다. 상품·부스 안내는 `docs/site-content.json`, 화면과 스타일은 `docs/index.html`과 `docs/style.css`에서 수정합니다. 원본 출처와 폰트 라이선스는 [사이트 출처](docs/SOURCE.md), [폰트 라이선스](docs/FONT-LICENSE.txt)에 있습니다. GitHub Pages는 `main` 브랜치의 `/docs`에서 배포합니다.

최종 버전 **1.1.1**에는 튜토리얼과 최신 안내를 포함했습니다. Windows 실행 파일과 ZIP은 위 다운로드 링크에서 받을 수 있습니다.
